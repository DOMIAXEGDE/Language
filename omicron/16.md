# 16.md — Book Sport Axiom Testing Command Sequence Blueprint

This blueprint uses `13.cpp`, `14.cpp`, `15.py`, and the optional kernel `17.py` to construct an on-demand axiom testing workflow.

The workflow is relative, not absolute: it proves, disproves, or quarantines candidate statements against the declared baseline axioms. It does not claim to solve all mathematics automatically. A candidate is accepted only when it has a direct baseline identity, a constructive derived identity, or a configured Boolean acceptance route. Otherwise the hard barrier rejects/quarantines it.

Standard mapping dictionary:

```text
a := accepted_information
x := rejected_by_hard_barrier
```

## 1. File layout

Place these files in one working directory:



Bash:


## 2. Initialize the axiom-testing project

Run:

```bash
python 17.py init
```

This creates:

```text

axiom_book_sport_13.fabric
axiom_book_sport_14.rules

```

The row headings are generated as pointers:

```text
axiom_000 => 000 I exist
axiom_001 => 001 I feel pain
...
axiom_065 => 065 What is not true, cannot be done
```

The column headings are instruction pointers:

```text
assert_baseline
prove_direct
prove_derived
disprove_contradiction
quarantine_unknown
barrier_check
note_external
```

## 4. Generate the static Book Sport axiom table with `13.cpp`

Direct command:

```bash
./13 --config axiom_book_sport_13.fabric --execute --overwrite --all --allow-large
```

Windows:

```powershell
.\13.exe --config axiom_book_sport_13.fabric --execute --overwrite --all --allow-large
```

Kernel shortcut:

```bash
python 17.py table
```

Expected output file:

```text
axiom_book_sport_table.txt
```

This is the static table. It contains every baseline axiom row crossed with every instruction column. Dynamic Boolean arithmetic is still deferred.

## 5. Evaluate the table with `14.cpp`

Direct command:

```bash
./14 \
  --table axiom_book_sport_table.txt \
  --rules axiom_book_sport_14.rules \
  --facts axiom_book_sport_14.facts \
  --execute --overwrite --all --allow-large \
  --output-target axiom_book_sport_14.acceptance.events.txt
```

Windows:

```powershell
.\14.exe `
  --table axiom_book_sport_table.txt `
```

## 8. On-demand proof testing

Direct proof by baseline identity:

```bash
python 17.py prove "I can learn"
```

Expected result:

```text
verdict: PROVED
result_symbol: a
candidate_state: accepted_information
baseline_ids: ["004"]
```

Constructive derived proof:

```bash
python 17.py prove "pain is a valid system signal"
```

Expected result:

```text
verdict: PROVED
result_symbol: a
candidate_state: accepted_information
baseline_ids: ["018"]
```

Direct disproof by contradiction against the baseline:

```bash
python 17.py disprove "Proof by contradiction enables learning"
```

Expected result:

```text
verdict: DISPROVED
result_symbol: x
candidate_state: rejected_by_hard_barrier
baseline_ids: ["007"]
```

Unknown candidate axiom:

```bash
python 17.py test "Every continuous function is differentiable"
```

Expected result under the present baseline:

```text
verdict: UNDECIDED_QUARANTINED
result_symbol: x
candidate_state: rejected_by_hard_barrier
```

This does not mean the statement is mathematically false in the outside world. It means the current baseline and rules do not prove it, so the hard barrier refuses acceptance.

## 11. How proving and disproving work

The testing model is intentionally fail-closed:

```text
PROVED
  Candidate is exactly a baseline axiom, or is a conclusion explicitly derived by a stored "Since ..., ..." axiom.

DISPROVED
  Candidate contradicts a stored baseline axiom through an explicit negation or a configured contradiction rule.

UNDECIDED_QUARANTINED
  Candidate is not proven and not disproven by the current baseline. It receives x because it is not accepted through the hard barrier.
```

This keeps the distinction between:

```text
not accepted
false
formally disproved
not yet tested
```

The event layer stores the acceptance/rejection mechanics; `17.py` performs external candidate comparison against the baseline.

## 12. How to add a new accepted mathematical axiom safely

Use this procedure:

1. Test it first:

```bash
python 17.py test "<candidate axiom>"
```

2. If it is quarantined, add a constructive derivation rule or manually add it to a new baseline revision.

3. Regenerate:

```bash
python 17.py init
python 17.py table
python 17.py accept
python 17.py normalize-events
```

4. Inspect through:

```bash
python 15.py
```

## 13. Baseline axiom set

The baseline contains axioms `000` through `065` exactly as supplied. They are persisted by `17.py` in `axiom_baseline.json` and mapped into `13.cpp` as row-heading pointers.

## 14. Minimal manual run without `17.py`

Create row and column heading files, then run:

```bash
./13 --table --execute --overwrite --all --allow-large \
  --table-name baseline_axiom_book_sport \
  --row-headings-file axiom_rows.txt \
  --column-headings-file axiom_columns.txt \
  --row-role baseline_axiom_pointer \
  --column-role axiom_test_instruction_pointer \
  --cell-role static_deferred_axiom_acceptance_cell \
  --boolean-engine 14.cpp \
  --boolean-contract dynamic_boolean_truth_arithmetic \
  --barrier-policy hard_closed_until_boolean_acceptance \
  --acceptance-state deferred_to_14.cpp \
  --cell-pointer-prefix bs_axiom_cell \
  --output-target axiom_book_sport_table.txt

./14 --table axiom_book_sport_table.txt \
  --rules axiom_book_sport_14.rules \
  --facts axiom_book_sport_14.facts \
  --execute --overwrite --all --allow-large \
  --output-target axiom_book_sport_14.acceptance.events.txt
```

Then inspect with:

```bash
python 15.py
```
